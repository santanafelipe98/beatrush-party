# Internacionalização (i18n)

Idiomas: **pt-BR** (padrão e idioma-fonte), **en** e **es**.

## Decisões

| Decisão | Motivo |
| --- | --- |
| **Sem biblioteca externa** | O app tem ~110 textos, sem plural complexo nem rotas por idioma. Um tradutor de ~40 linhas, tipado, cobre tudo e não adiciona dependência. Migrar para `next-intl`/`i18next` no futuro é simples: as chaves e a API `t()` são as mesmas. |
| **Idioma em cookie, sem prefixo na URL** | O QR Code e os links `/play?code=XXXX` precisam ser idênticos para qualquer idioma. Prefixos (`/en/play`) quebrariam o fluxo de compartilhar o código. |
| **Idioma por aparelho** | Cada aparelho escolhe o seu. A TV pode estar em inglês enquanto um celular está em espanhol e outro em português. O servidor **não** conhece idioma. |
| **Servidor envia códigos, não textos** | Erros (`room_full`, `name_taken`…) e o estado do jogo trafegam como dados; quem traduz é o cliente. Mantém o protocolo neutro (ver `03-realtime-protocol.md`). |
| **Gêneros: id interno ≠ rótulo** | `"Anos 80"` continua sendo o id no protocolo, no Zod e no catálogo do Deezer. Só a **exibição** é traduzida (`genre.<id>`), então uma TV em inglês e um celular em português votam no mesmo gênero. |
| **Nomes de músicas/artistas não são traduzidos** | Vêm do Deezer. |

## Como o idioma é escolhido

1. Cookie `beatrush-locale` (escolha explícita, validade de 1 ano), senão
2. cabeçalho `Accept-Language` do navegador (respeita pesos `q`; `pt-PT`→pt-BR, `en-GB`→en, `es-MX`→es), senão
3. pt-BR.

O layout (servidor) resolve isso e passa `initialLocale` ao `I18nProvider`. O HTML inicial já sai no
idioma certo (sem "piscar" na hidratação) e com `<html lang>` correto. O seletor `PT | EN | ES`
grava o cookie e atualiza a tela na hora.

## Estrutura

```
src/lib/i18n/
  locales.ts        idiomas, cookie, negociação de Accept-Language
  messages/
    pt-BR.ts        idioma-fonte: define as chaves (MessageKey)
    en.ts, es.ts    tipados como Record<MessageKey, string>
  translate.ts      createTranslator: t(), n() (números), ordinal()
  provider.tsx      I18nProvider + useI18n() (cliente)
  server.ts         getLocale()/getTranslator() (servidor)
src/components/ui/language-switcher.tsx
```

## Como usar

```tsx
const { t, n, ordinal } = useI18n();
t("lobby.connected", { count: 3, max: 8 });   // "3 / 8 conectados"
t(`genre.${genre}`);                          // rótulo do gênero
n(1840);                                      // "1.840" (pt) | "1,840" (en)
ordinal(2);                                   // "2º" | "2nd"
```

## Como adicionar um texto ou idioma

- **Texto novo:** adicione a chave em `messages/pt-BR.ts`; o TypeScript passa a exigi-la em `en.ts` e `es.ts`.
- **Novo idioma:** crie `messages/<codigo>.ts`, inclua em `LOCALES`, `LOCALE_INFO`, `MESSAGES` e no
  `negotiateLocale`/`INTL_LOCALE`.
- O teste `i18n.test.ts` garante que todos os idiomas têm as mesmas chaves, nenhum texto vazio e os
  mesmos placeholders (`{n}`, `{name}`…).

## Limitações conhecidas

- Sem plural gramatical: os textos foram escritos para não depender dele ("Jogadores: 3").
- Revisão de tradução: en/es foram escritos por IA e merecem revisão por falantes nativos,
  principalmente expressões como "Qual vai ser a vibe?" → "What's the vibe?" / "¿Cuál será el ambiente?".
- Idioma muda por aparelho; não há sincronização entre TV e celulares (por decisão).
- O título da aba (`BeatRush Party`) é igual em todos os idiomas; só a descrição é traduzida.
